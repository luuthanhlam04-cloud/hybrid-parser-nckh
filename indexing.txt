2.4. Chunking Strategy
Đây là bước quan trọng nhất.
Option A — Structure-aware chunking (khuyến nghị)
Cơ chế: Cắt theo ranh giới Điều/Khoản/Điểm.
python
def structure_aware_chunk(article):
    chunks = []
    
    # Nếu điều ngắn (< 500 tokens) → giữ nguyên
    if count_tokens(article['full_text']) < 500:
        chunks.append({
            'id': f"{article['id']}_full",
            'text': article['full_text'],
            'chunk_type': 'article_full',
            'parent_id': article['id']
        })
    else:
        # Cắt theo Khoản
        for clause in article['clauses']:
            chunks.append({
                'id': f"{article['id']}_khoan_{clause['number']}",
                'text': clause['text'],
                'chunk_type': 'clause',
                'parent_id': article['id'],
                'article_number': article['article_number']
            })
    
    return chunks
Ưu điểm:
Giữ nguyên cấu trúc pháp lý.
Citation chính xác.
Không cắt giữa câu.
Nhược điểm:
Điều dài → chunk dài → embedding kém.
Điều ngắn → chunk ngắn → thiếu context.
Option B — Token-based chunking với overlap
python
def token_chunk(text, chunk_size=512, overlap=50):
    tokens = tokenize(text)
    chunks = []
    
    for i in range(0, len(tokens), chunk_size - overlap):
        chunk_tokens = tokens[i:i + chunk_size]
        chunks.append({
            'text': detokenize(chunk_tokens),
            'chunk_type': 'token_chunk',
            'char_start': i,
            'char_end': i + chunk_size
        })
    
    return chunks
Ưu điểm: Đơn giản, chunk size đồng đều.
Nhược điểm: Cắt giữa câu, mất cấu trúc.
Option C — Hybrid chunking (khuyến nghị cho benchmark)
Cơ chế:
Điều ngắn (< 500 tokens) → 1 chunk.
Điều dài (≥ 500 tokens) → cắt theo Khoản.
Khoản dài (≥ 1,000 tokens) → cắt theo Điểm.
python
def hybrid_chunk(article, max_tokens=512):
    if count_tokens(article['full_text']) <= max_tokens:
        return [article_full_chunk(article)]
    
    chunks = []
    for clause in article['clauses']:
        if count_tokens(clause['text']) <= max_tokens:
            chunks.append(clause_chunk(clause))
        else:
            # Cắt tiếp theo Điểm
            for point in clause['points']:
                chunks.append(point_chunk(point))
    
    return chunks
Kết quả: Chunk size 200-500 tokens, giữ cấu trúc.

def embed_chunks(chunks, batch_size=32):
    texts = [c['text'] for c in chunks]
    
    embeddings = model.encode(
        texts,
        batch_size=batch_size,
        show_progress_bar=True,

Bước 3 — Reranker
Chọn model:
Khuyến nghị: BGE-reranker-large — multilingual, free, hiệu quả.
python
from sentence_transformers import CrossEncoder

reranker = CrossEncoder('BAAI/bge-reranker-large')
reranker.to('cuda')

def rerank(query, candidates, top_k=5):
    pairs = [[query, c['text']] for c in candidates]
    scores = reranker.predict(pairs)
    
    ranked = sorted(zip(candidates, scores), key=lambda x: -x[1])
    return [c for c, s in ranked[:top_k]]
Bước 4 — Hybrid Search
Cơ chế:
BM25 retrieve top-50.
Dense retrieve top-50.
Reciprocal Rank Fusion (RRF) gộp 2 danh sách.
Reranker top-20.
python
def hybrid_search(query, top_k=5):
    # BM25
    bm25_scores = bm25.get_scores(tokenize_vietnamese(query))
    bm25_top = np.argsort(bm25_scores)[-50:][::-1]
    
    # Dense
    query_emb = model.encode(query, normalize_embeddings=True)
    dense_scores = np.dot(embeddings, query_emb)
    dense_top = np.argsort(dense_scores)[-50:][::-1]
    
    # RRF
    rrf_scores = {}
    for rank, idx in enumerate(bm25_top):
        rrf_scores[idx] = rrf_scores.get(idx, 0) + 1/(60 + rank)
    for rank, idx in enumerate(dense_top):
        rrf_scores[idx] = rrf_scores.get(idx, 0) + 1/(60 + rank)
    
    # Top 20 cho reranker
    top_20 = sorted(rrf_scores.keys(), key=lambda x: -rrf_scores[x])[:20]
    candidates = [chunks[i] for i in top_20]
    
    # Rerank
    return rerank(query, candidates, top_k)
Thời gian: BM25 index ~1 phút, reranker load ~2 phút.

5. Khó khăn và bất cập
5.1. Khó khăn chung
1. Kaggle GPU limit.
T4x2: 16GB VRAM, 30h/tuần.
BGE-M3: ~2GB VRAM.
BGE-reranker-large: ~2GB VRAM.
→ Đủ chạy cùng lúc.
2. Session timeout.
Kaggle session tối đa 12h.
Indexing 3 hệ thống: ~2h → OK.
3. Storage limit.
Kaggle output: 20GB.
Vector DB + Graph: ~100MB → OK.
5.2. Khó khăn riêng từng hệ thống
Vector RAG:
Embedding model download lần đầu ~2GB → cần internet.
LanceDB/Qdrant cần config đúng.
Hybrid RAG:
BM25 cần tokenizer tiếng Việt (underthesea).
RRF cần tune tham số k=60.
Reranker chậm hơn (mỗi query ~0.5s).
LightRAG:
LLM extraction có thể fail → cần retry.
Entity dedup là vấn đề.
Graph có thể bị fragment nếu extraction kém.
5.3. Bất cập trong benchmark
1. Chunking không đồng nhất giữa 3 hệ thống.
Vector RAG dùng 1 chunk strategy.
Hybrid dùng cùng strategy.
LightRAG có internal chunking riêng.
→ Không hoàn toàn fair.
Cách xử lý: Document rõ chunking strategy trong luận.
2. Embedding model không giống nhau.
Nếu LightRAG dùng model khác → không fair.
Cách xử lý: Cấu hình LightRAG dùng cùng BGE-M3.
3. Reranker ảnh hưởng đến kết quả.
Hybrid RAG có reranker → lợi thế.
Vector RAG không có → thiệt.
Cách xử lý: Đây là điểm khác biệt paradigm. Document rõ.
